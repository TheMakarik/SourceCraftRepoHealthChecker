# Крупный репозиторий — доказательство сквозного прогона (TZ 9.2 / 11.1)

Документ фиксирует, что сервис выдерживает анализ **крупного репозитория** и что критерий ТЗ
проверяется автоматически.

## 1. Критерий ТЗ

Крупным считается репозиторий, у которого выполнено **хотя бы одно** условие:

| Показатель | Порог |
|---|---|
| Отслеживаемых файлов в рабочей копии | ≥ 10 000 |
| Коммитов в истории | ≥ 20 000 |
| Размер рабочей копии | ≥ 500 МБ |

## 2. Генератор синтетического репозитория

Для воспроизводимой проверки критерия используется фикстурный генератор интеграционного теста:

- `Tests/SourceCraftRepoHealthChecker.IntegrationTests/Scripts/create-large-repository.ps1`

При запуске теста **без** `SRHC_LARGE_REPO_PATH` он автоматически создаёт синтетический репозиторий
с нужными характеристиками (по умолчанию 10 000 файлов, 20 коммитов, 5 авторов). В файлах намеренно
оставлены `TODO`/`FIXME`, добавлены README, LICENSE и два релизных тега, чтобы Code health,
Documentation и Activity-метрики были непустыми.

Если нужно указать реальный крупный репозиторий — задайте `SRHC_LARGE_REPO_PATH` (тест его не генерирует).

## 3. Интеграционный тест

Тест: `Tests/SourceCraftRepoHealthChecker.IntegrationTests/LargeRepositoryTests`.
Сквозной прогон помечен `[Trait("Category", "LargeRepository")]` и запускается **только** если
задана переменная окружения `SRHC_LARGE_REPO_PATH` (легаси-имя `LARGE_REPO_PATH`). Без неё тест
не начинает анализ, пишет в вывод сообщение о пропуске и завершается успешно (не падает). Он
проходит полный путь:
git-история → контрибьюторы → релизы → Code health → Documentation → структура папок → движок
Health Check, и проверяет, что репозиторий действительно крупный, а Score попадает в 0–100.

Интеграционным тестам также нужен PostgreSQL (общий фикстур проекта), см. `SRHC_TEST_POSTGRES`:

```bash
docker start srhc-postgres   # 127.0.0.1:55432, если контейнер остановлен

export SRHC_LARGE_REPO_PATH=/tmp/srhc-large-repository
export SRHC_TEST_POSTGRES="Host=127.0.0.1;Port=55432;Database=sourcecraft_repo_health_tests;Username=postgres;Password=postgres"

dotnet test Tests/SourceCraftRepoHealthChecker.IntegrationTests \
  --filter "Category=LargeRepository"
```

## 4. Полученный результат

Прогон от **2026-09-29**, .NET SDK 10.0.110, `srhc-postgres` (PostgreSQL 16, порт 55432).

| Параметр | Значение |
|---|---|
| Путь | `/tmp/srhc-large-repository` |
| Отслеживаемых файлов | **10 002** (≥ 10 000 ✓) |
| Коммитов | 20 |
| Авторов | 5 |
| Релизных тегов | 2 |
| Размер на диске (`du`) | 46 МБ |
| Размер по фактическим данным файлов (тест) | 3 МБ |
| Время генерации | ≈ 8,5 с |
| **Время анализа крупного репозитория тестом** | **≈ 1,21 с** |

Полный лог: `/tmp/srhc-large-repo-test.log` (временный, вне репозитория).

> Критерий «коммиты ≥ 20 000» проверяется тем же генератором: `--commits 20000`. Критерий
> «размер ≥ 500 МБ» генератор по умолчанию не покрывает (файлы крошечные, ~100 байт каждый) —
> для него нужен репозиторий с крупными бинарными файлами. Тест принимает любой репозиторий, где
> выполнено **хотя бы одно** из трёх условий, поэтому для обязательного доказательства достаточно
> критерия по файлам (10 000+), который и зафиксирован в таблице выше.

## 5. Как выложить такой репозиторий в SourceCraft

Чтобы прогнать сервис на реальном каталоге SourceCraft (не локальной копии), репозиторий нужно
загрузить туда.

1. Создать пустой репозиторий в SourceCraft — через UI или REST API SourceCraft
   (`https://api.sourcecraft.tech`, тот же API, что использует сервис) с PAT в `Authorization`:
   `POST /repos` с именем/видимостью (для такого «нагрузочного» репозитория — приватный).
   Забрать выданный `sourceCraftId`.
2. Добавить remote и зеркально запушить всю историю, теги и ветки:

   ```bash
   cd /tmp/srhc-large-repository
   git remote add sourcecraft https://git.sourcecraft.dev/<owner>/<repo-name>.git
   git push --mirror sourcecraft
   ```

   `--mirror` переносит все refs (ветки, теги, `refs/remotes`), полностью повторяя локальный
   репозиторий.
3. Запустить анализ: сервис склонирует репозиторий во временную копию, прочитает git-историю и
   посчитает Score. Локальный тест `LargeRepositoryTests` — это автономная проверка того же пути
   без подключения к SourceCraft.

Тот же приём подходит для реального крупного репозитория: его достаточно указать в
`SRHC_LARGE_REPO_PATH` (тест) или загрузить в SourceCraft (полный сценарий сервиса).
