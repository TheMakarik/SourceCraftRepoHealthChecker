# Возможности проекта

Статусы: **✅ по ТЗ** — обязательное; **⭐ сверх ТЗ** — дополнительные улучшения; **❌ не сделано** — незакрытые пункты ТЗ.

## Оценка здоровья репозитория

- ✅ **Итоговый балл 0–100** по шести категориям с детализацией, воспроизводимый и объяснимый.
- ✅ **Шесть категорий**: Security (результаты AppSec), Code health (TODO/FIXME и старый техдолг), Активность (коммиты, контрибьюторы, релизы, merge request’ы), Документация (README/лицензия/CONTRIBUTING/CODEOWNERS/инструкции запуска), CI/CD (пайплайны), Issues.
- ✅ **Веса категорий настраиваются** (ориентир: Security 20%, Code health 20%, Активность 15%, Документация 15%, CI/CD 15%, Issues 15%).
- ✅ **Нормализация метрик** по заданным границам; балл категории — взвешенное среднее метрик, поэтому цифры в объяснении сходятся с оценкой.
- ✅ **«Нет данных» — отдельный статус**, а не плохой результат: недоступные категории не тянут балл вниз, веса доступных пересчитываются.
- ✅ **Устойчивость методики** зафиксирована тестами: серьёзные проблемы заметно снижают балл, исправления повышают, отсутствие данных не ухудшает, популярность не подменяет здоровье.
- ✅ **Рекомендации** с фактами: проблема, почему важна, подтверждающие данные, действие, приоритет, **количественная** оценка влияния на балл и ссылка на источник (файл/pipeline/уязвимость/commit/issue/MR).

## Данные и аналитика

- ✅ Сбор данных из **API SourceCraft**, из **git-истории репозитория** и из **системы безопасности AppSec** (SAST/SCA/scanner секретов).
- ✅ **Устойчивость к сбоям источников**: повторные попытки, таймауты и circuit breaker для HTTP-клиентов; недоступный источник помечает только свою категорию.
- ✅ **Кэш рабочей копии репозитория** на локальном диске: ограниченное время жизни (TTL), лимит числа кэшированных копий и фоновая автоочистка; исходный код не хранится дольше необходимого. S3-совместимое хранилище используется только для ключей DataProtection (опционально).
- ⭐ **Обнаружение аномалий активности**: всплеск коммитов/merge request’ов от нового автора за короткий срок; небольшие изменения от ранее неактивного автора. Пороги настраиваются, по аномалиям формируются рекомендации.
- ⭐ **Проверка структуры папок**: число файлов и каталогов, максимальная глубина, файлы в корне, самая крупная папка. Отдельная проверка, не требующая корневых README/лицензии.

## Пользовательские сценарии

- ✅ **Публичный рейтинг**: место, проект, ссылка, балл, лайки, язык, последняя активность; фильтр по языку (регистр не важен), сортировки по баллу/лайкам/активности, постраничная навигация. Приватные репозитории в публичный рейтинг не попадают.
- ✅ **Страница анализа**: итоговый балл, категории, сильные и слабые стороны, объяснение расчёта по метрикам, рекомендации, отметка «Нет данных», дата последнего анализа.
- ✅ **Анализ своего репозитория после входа через Я ID**: выбор доступного репозитория, запуск анализа; доступ к данным приватного репозитория — только его владельцу (токен доступа хранится в зашифрованном виде).
- ✅ **Периодический пересчёт**: фоновый планировщик (`PeriodicTimer`) раз в `RepositoriesRefreshMinutes` выбирает устаревшие репозитории и ставит их в очередь; задания обрабатывают воркеры с настраиваемой конкурентностью и повторами. Тик планировщика защищён advisory-локом PostgreSQL, поэтому в кластере ставит задачи только одна реплика. Очередь — **в памяти процесса** (`ChannelAnalysisQueue`), поэтому она не общая между инстансами и не переживает рестарт (см. «Не сделано / ограничения»).
- ✅ **Выгрузка отчёта**: Markdown, JSON, HTML и PDF (форматов больше чем в ТЗ).
- ✅ **Веб-интерфейс**: отдельное SPA (React + TypeScript + Fluent UI) с публичным рейтингом, страницей анализа, сравнением, историей, структурой, bus factor и настройками PAT и провайдера/модели ИИ.

## Развёртывание и эксплуатация

- ❌ **Serverless-развёртывание (Yandex Cloud)**: stateless-функции, обработчик очереди сообщений и триггер по расписанию не реализованы. Фактически сервис — единый ASP.NET-хост с фоновыми сервисами (`PeriodicTimer`, in-memory очередь); веб-часть запускается в контейнере.
- ✅ **База данных**: PostgreSQL со схемой и миграциями, автоматическим применением на старте (при включённом `DatabaseOptions:AutoMigrate`) и повторными попытками при сбоях.
- ✅ **Ключи DataProtection** (подпись тикет-куки) персистятся: по умолчанию — в локальный каталог/том, опционально — в S3-совместимое хранилище (`DataProtectionStorageOptions.Bucket`), что позволяет переживать рестарт и работать между инстансами.
- ✅ **Секреты** не хранятся в репозитории: значения берутся из переменных окружения/секретов; при отсутствии обязательного ключа шифрования сервис не стартует.
- ✅ **Структурированное логирование** Serilog с читаемым консольным выводом (асинхронный Console-sink). Отправки в облачный журнал сейчас нет.
- ✅ **Единая обработка ошибок** с корректными HTTP-кодами (401/403/404/503 и т.п.).
- ⭐ **Непрерывная интеграция** настроена и для GitHub Actions, и для CI/CD SourceCraft; обе системы вызывают одни и те же PowerShell-скрипты.
- ⭐ **Поддержка крупных репозиториев**: неполный клон, потоковое чтение истории, ограничения по размеру/времени. Полный сквозной прогон на крупном репозитории пока не подтверждён (см. «Не сделано / ограничения»).

## Работа с ИИ (сверх ТЗ)

- ⭐ **AI-резюме** через единый интерфейс работы с моделями; поддерживаются провайдеры: OpenAI, Anthropic, Google Gemini, Yandex, DeepSeek. Пользователь сам выбирает провайдера и модель, настройки хранятся в зашифрованном виде.
- ⭐ **AI-разборы разных видов** (поверх фактов анализа, без выдумок): приоритизированные **рекомендации**, **объяснение** расчёта Score, **план улучшения** (quick wins и долгие шаги), **триаж находок безопасности**, **прогноз рисков** падения Score. Промпты настраиваются через `IOptions<AiOptions>`.

## Не сделано / ограничения

- ❌ **Полный сквозной прогон на крупном репозитории** (все шесть категорий → балл → сохранение) и граница «рабочая копия ≥500 МБ» не подтверждены целиком.
- ❌ **Сопоставление уровней/статусов безопасности AppSec** не проверено на реальных данных.
- ❌ **Автоматический деплой/демо-стенд** и размещение проекта в SourceCraft — организационные задачи.
- ❌ **Публичный API и quality badges** как отдельные внешние артефакты не реализованы (есть внутренний JSON API и веб-страницы). История и сравнение проектов, индекс достоверности и обнаружение аномалий — реализованы.

## Быстрый старт

- Соберите и протестируйте бэкенд (`dotnet build` / `dotnet test` или скрипты в `Scripts/`) и соберите фронтенд (`npm run build` в `Frontend/`).
- Для запуска бэкенда укажите строку подключения к PostgreSQL, ключ шифрования токенов и, при необходимости, параметры S3-совместимого хранилища для ключей DataProtection.
- Публичные эндпоинты и внутренний контракт описаны в `Docs/API.md`; архитектура, формула Score и метрики — в `Docs/ARCHITECTURE.md`.
