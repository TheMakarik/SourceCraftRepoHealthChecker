# Источники данных

Единственный источник — действующие **API и CLI SourceCraft**. Готовых выгрузок нет, импорт репозиториев с внешних Git-платформ не выполняется: анализируется только то, что размещено в SourceCraft.

## Используемые API/CLI SourceCraft

Публичный REST API: `https://api.sourcecraft.tech` (`SOURCECRAFT_API_URL`, `internal/sourcecraft/endpoints.go`).

| Что | Откуда |
|---|---|
| Публичный каталог репозиториев | `GET /repos`, `GET /repos/id:{id}` |
| Репозитории пользователя | `GET /me/repos` |
| Профиль пользователя | `GET /user` |
| Issues и комментарии | `GET /repos/id:{id}/issues`, `GET /issues/id:{id}/comments` |
| Merge requests и комментарии | `GET /repos/id:{id}/pulls`, `GET /pulls/id:{id}/comments` |
| Релизы | `GET /repos/id:{id}/releases` |
| CI/CD | `GET /repos/id:{id}/cicd/runs` |
| Дерево файлов | `GET /repos/id:{id}/trees` |
| Коммиты, contributors, TODO/FIXME, состав документации | локальный **git** (clone + `git log`/`ls-files`/`show`), т.к. в API этих данных нет |

Доступ к API — по токену в заголовке `Authorization: Bearer <PAT/IAM>`. Без пользовательского токена Go-сервис использует сервисный `SOURCECRAFT_TOKEN` (только публичные данные).

## Вход через Я ID и его границы

Я ID используется **только для установления личности**:

- Go-сервис регистрирует OAuth-приложение на `oauth.yandex.ru` (`YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `YANDEX_REDIRECT_URI`, права `login:info login:email`) и обменивает код на профиль (id, login, displayName, email) через `login.yandex.ru/info`.
- **Я ID не даёт доступа к API SourceCraft.** Публичный API принимает только PAT и IAM-токены Yandex Cloud, а обмен OAuth-токенов Яндекса на IAM закрыт для новых токенов с 01.06.2026. Поэтому токен Яндекса сразу отбрасывается и наружу не отдаётся.
- Следствие: для приватных репозиториев (`GET /auth/me`, `GET /auth/repositories`, снапшоты) пользователь **по-прежнему передаёт свой PAT SourceCraft**.
- Профиль SourceCraft не отдаёт email — `SourceCraftUser.Email` всегда `null`.
- `state` генерирует и после callback сверяет C# (защита от CSRF); Go-сервис stateless и сверить state не может. Код подтверждения одноразовый, живёт 10 минут, повторный/просроченный даёт `400 invalid_grant`.

## Security = «Нет данных»

- Security-оценка строится **только** на реальных результатах **AppSec SourceCraft** (SAST, SCA, secret scanning). Имитация собственного сканирования ТЗ запрещена.
- На момент фиксации (2026-09-25) AppSec **отсутствует в публичном API**, поэтому эндпоинт `GET /repositories/{id}/security/findings` честно отвечает `Unavailable` (`reason = "SourceCraft public API does not expose AppSec findings yet"`), а категория Security получает статус **«Нет данных»** — без штрафа к итоговому Score.
- Ядро добавляет явную рекомендацию-пометку «Подключите AppSec SourceCraft» с приоритетом `Low`, чтобы пользователь понимал, как включить реальную оценку безопасности. Когда AppSec появится в API (или будет подключён), достаточно начнёт отдавать `SecurityFinding` — код ядра уже готов считать по критичности.

## Известные ограничения API (на 2026-09-25)

- **AppSec** — отсутствует в публичном API (см. выше).
- **Коммитов в API нет.** `activity/commits` и `activity/contributors` считаются по git-истории; `Contributor.Login` — имя автора из git, авторы объединяются по email. Боты распознаются по имени/email (`[bot]`, `-bot`, dependabot, renovate и т.п.).
- **Merge request**: у PR нет отдельных `merged_at`/`closed_at`; для завершённых PR берётся `updated_at`. `FirstResponseAt` и `ReviewCommentsCount` считаются по комментариям.
- **CI**: у запусков нет ветки (`PipelineRun.Branch` пустой); публичного id нет — используется `slug`.
- **Лайки**: `LikesCount` — сумма всех rating-реакций (Like, Heart, Diamond).
- **Релизы**: учитываются только опубликованные (`status == "published"`).
- **Issues**: статус завершённых определяется по `status_type` (`completed`/`cancelled`).

## Правила хранения кода

Исходный код не хранится дольше и в большем объёме, чем нужно для анализа:

- Персистентны только **нормализованные метрики** (в БД C#: репозиторий, прогон, баллы категорий, рекомендации). Сам код в БД не попадает.
- Клон репозитория — **временный** и живёт в S3-совместимом хранилище (TTL `SNAPSHOT_TTL`, по умолчанию 3 часа) либо на эфемерном диске контейнера в пределах одного прогона. Полный список механизмов удаления — в [architecture.md](architecture.md#s3-снапшоты-с-ttl).
- Клон делается **один раз на прогон** и переиспользуется сборщиками; формат компактный (`--bare`, `--single-branch`, `--filter=blob:none`, опционально `--depth`).
- Содержимое кода не попадает в логи, метрики, трассировку и ответы; git-креды — только через переменные окружения процесса git, не в URL/argv/логах.
- Данные закрытого репозитория обрабатываются только в рамках прав авторизованного пользователя: перед операцией со снапшотом сервис проверяет через API, что токен запроса видит репозиторий.

## Устойчивость к недоступности источников

- Ретраи с экспоненциальным backoff и соблюдением `Retry-After`; ограничение частоты запросов (`SOURCECRAFT_RPS`).
- Circuit breaker на недоступный SourceCraft (serverless-точка входа): после нескольких подряд сбоев запросы отклоняются на cooldown, затем пропускается пробная попытка. `4xx` сбоем не считается.
- Сбой одного источника даёт `Unavailable` только для своей категории — остальные категории продолжают считаться.
