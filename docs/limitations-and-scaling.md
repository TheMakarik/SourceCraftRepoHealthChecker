# Ограничения и масштабирование

## Ограничения решения

- **Только SourceCraft.** Единственный источник — API и CLI SourceCraft; импорт с внешних Git-платформ не поддерживается.
- **Security без AppSec недоступен.** Публичный API SourceCraft не отдаёт SAST/SCA/secret scanning, поэтому категория Security получает «Нет данных» (без штрафа) и пометку «Подключите AppSec SourceCraft». Имитация сканирования запрещена ТЗ. См. [data-sources.md](data-sources.md).
- **Вход через Я ID не даёт доступа к API SourceCraft.** API принимает только PAT/IAM, поэтому приватные репозитории требуют PAT пользователя; Я ID устанавливает только личность.
- **Ряд фактов выводится из git**, а не из REST (коммиты, contributors, TODO/FIXME, документация), что требует клонирования и локального git.
- **Рекомендации без отдельных артефактов.** Привязка идёт к кодам метрик (`SourceReference`), а не к конкретному файлу/pipeline/vulnerability: у использованных API нет стабильных публичных ссылок на находки.
- **Выгрузка только Markdown.** PDF не реализован.
- **HTTP-поверхность авторизации и запуска анализа в Presenter не подключена.** Порт/адаптер Я ID, use case'ы `IAuthenticateUserUseCase`/`IGetUserRepositoriesUseCase` и `AnalyzeRepositoryUseCase` реализованы, но соответствующие маршруты не замаплены; анализ читается из уже сохранённых прогонов.
- **Фоновый планировщик не зарегистрирован.** `ScheduledAnalysisRunner`/`ScheduledAnalysisBackgroundService` и `SchedulingOptions` реализованы, но не подключены в DI/конфигурацию.
- **Часть Go-развёртывания зависит от инфраструктуры.** S3-совместимое хранилище обязательно (`S3_ENDPOINT`, `S3_BUCKET`); без него сервис поднимается, но эндпоинты, требующие клона, работать не будут.

## Часть со звёздочкой (опционально, не реализовано)

- Расширенный рейтинг, история и сравнение проектов.
- Углублённая аналитика: review, bus factor, карта владельцев.
- Публичный API для сторонних потребителей и quality badges.
- AI-summary и AI-рекомендации (есть только сущность `UserAi`, перечень провайдеров и шифрование токена — сценариев нет).
- Защита публичного рейтинга от накрутки.

Бонусные функции не компенсируют отсутствие обязательной части.

## Крупные репозитории

Порог «крупного» репозитория по ТЗ: **≥ 10 000** отслеживаемых файлов, **или ≥ 20 000** коммитов, **или ≥ 500 МБ** рабочей копии.

Подход:

- Клон — только по правилам компактного хранения: `--bare`, `--single-branch`, `--filter=blob:none` (partial clone), опционально `--depth` (shallow). Полный checkout — только там, где реально нужно содержимое файлов.
- Анализ — потоковый: `git log`, `git ls-files` и т.п. без полного checkout и без загрузки содержимого в память.
- Жёсткие лимиты: `GIT_MAX_REPO_MB` (размер клона и распаковки, по умолчанию 2048 МБ) и `GIT_CLONE_TIMEOUT` (по умолчанию 15 минут). При превышении прогон прерывается, источник отвечает `Unavailable` — **деградация вместо падения**.
- Рабочая копия не персистентна: S3-снапшот с TTL удаляется после анализа, эфемерный клон — по завершении запроса.
- Снапшот создаётся один раз на прогон и переиспользуется всеми сборщиками (activity, code-health, documentation), чтобы не клонировать репозиторий многократно.

## Устойчивость к недоступности источников

- **Ретраи** с экспоненциальным backoff; учитывается заголовок `Retry-After`.
- **Rate limiting** к API SourceCraft (`SOURCECRAFT_RPS`, по умолчанию 10 запросов/сек), соблюдение лимитов платформы.
- **Circuit breaker** (`internal/sourcecraft/breaker.go`, serverless-точка входа): после `SOURCECRAFT_BREAKER_THRESHOLD` (5) подряд сбоев (ошибка транспорта, `5xx`, `429`) запросы отклоняются на `SOURCECRAFT_BREAKER_COOLDOWN` (30 с), затем пропускается одна пробная попытка. `4xx` сбоем не считается.
- **Изоляция сбоя**: сбой одного источника даёт `Unavailable` только для своей категории, остальные категории рассчитываются. Частичные данные предпочтительнее падения.
- **Все операции с `context.Context`** и отменой; таймауты на HTTP-вызовы и клонирование.
- **Stateless** Go-сервиса: состояние не в памяти инстанса (токены/курсоры — в запросе), что делает ретраи и горизонтальное масштабирование безопасными.
- **Идемпотентность**: повторный `CreateSnapshot` по `(repositoryId, runId)` не клонирует заново; потребитель очереди обрабатывает повторы идемпотентно.
- **Страховка хранилища**: если S3 временно недоступен, сервис всё равно поднимается и лёгкие эндпоинты работают.

## Периодический пересчёт

- Таймер-триггер вызывает `POST /internal/snapshots/reap` (очистка просроченных снапшотов); локально то же делает `SNAPSHOT_REAP_INTERVAL`.
- Message Queue принимает задачи анализа и распределяет их по репозиториям, обеспечивая устойчивость и разгрузку.
- Каждый анализ фиксируется как `AnalysisRun` со статусом (`Pending`/`Running`/`Completed`/`Failed`) и временем; рейтинг и страница анализа читают последний **завершённый** прогон, поэтому повторный сбор и пересчёт Score не ломают отображение.

## Масштабирование

- **Горизонтальное** масштабирование: stateless-функции и контейнеры; конкурентность ограничивается настройками (`SERVICECRAFT_CONCURRENCY`, лимиты платформы).
- **Serverless-развёртывание (Yandex Cloud)**: лёгкие HTTP-вызовы — в Cloud Functions, тяжёлый анализ — в Serverless Containers, задачи — через Message Queue, расписание — через Timer trigger, буфер репозитория — в Object Storage.
- **Разделение нагрузок**: тяжёлое (клон, git-история, TODO/FIXME) не идёт в FaaS с ограничением времени; это Container.
- **Пропускная способность API**: пагинация (`page_token`), ограничение числа забираемых issues/MR/CI-запусков (`SERVICECRAFT_MAX_ITEMS`, по умолчанию 500) и числа запросов комментариев (`SERVICECRAFT_MAX_RESPONSE_LOOKUPS`, по умолчанию 100).
- **Наблюдаемость**: structured logs, метрики латентности/ошибок/размеров клонов, распределённая трассировка; метрики по категориям — доли `Available`/`NoData`/`Unavailable`.
- **Ограничение объёма кода**: персистентны только нормализованные метрики, поэтому рост числа репозиториев не увеличивает объём хранимого исходного кода.
