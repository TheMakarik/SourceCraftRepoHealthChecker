# Старт фронтенда

Перед первой строкой кода сделай подготовку.

## 1. Входные данные
- Попроси у вайбкодера **ТЗ (PDF хакатона)** и прочитай его. На Linux переведи PDF в текст: `pdftotext -layout "<файл>.pdf" /tmp/tz.txt`, затем изучи.
- Изучи API бэкенда: папка `Backend/` (эндпоинты `Presenter`), а также `Docs/API.md`.
- Попроси у вайбкодера **макеты/скриншоты дизайна**.

## 2. Выбор стека
- Язык — **TypeScript** (правила в скилле `frontend-stack`).
- Фреймворк — любой с поддержкой TS и хорошей базой; оцени минимализм, поддержку статики/SSR и совместимость с serverless.
- Подбери **готовые библиотеки** под дизайн (компоненты, таблицы, графики, иконки). Используй их, а не самодельные костыли.
- Если дизайн похож на **Fluent** (Windows) — подключи готовые Fluent CSS-стили.

## 3. Хостинг
- Всё разворачивается в **serverless Yandex Cloud**; статику можно отдавать из Object Storage/Sites. Учитывай лимиты serverless.

## 4. MCP
- Выбери MCP для веба и подключи (работаешь через Claude Code). Если для подключения нужен рестарт — попроси пользователя перезапустить.

## 5. Компонентная архитектура
- Раздели UI на **независимые компоненты** с чёткими границами и минимумом общих файлов, чтобы над ними могли параллельно работать субагенты.

## 6. Авторизация и токен (PAT) — обязательно учесть

- Вход — через **Я ID** (`/auth/login` → `/auth/callback`): это только identity и личный кабинет, **токен API он не даёт**.
- Токен Яндекса API SourceCraft не принимает; PAT получить автоматически нельзя. Пользователь создаёт его **вручную** (SourceCraft → Access → Personal access tokens → Generate) и вводит у нас (`POST /api/me/sourcecraft-token`).
- **До PAT** видно: публичный рейтинг (`/rating`, `/api/repositories`), анализ публичных репо, свой профиль (`/api/me`).
- **После PAT** открывается: список своих/приватных репозиториев (`/api/me/repositories`), их issues/pulls/CI/security. Приватная страница доступна только владельцу.
- Без AppSec/токена категория Security = **«Нет данных»** (не штраф).
- UX: сделай понятную форму ввода PAT с короткой инструкцией и пояснением, зачем он нужен и что станет доступно; показывай разницу «до/после». Токен хранится зашифрованно и повторно не показывается.
- В **публичный рейтинг не включай** метрики, доступные только с пользовательским токеном — иначе оценки репозиториев несопоставимы.

## 7. Dev-скрипты (нужно докомплектовать под фронтенд)

- В `Dev/` лежат `setup-deps.sh` и `setup-deps.bat` — они ставят зависимости **только для бэкенда (.NET)** через apt/dnf или winget/choco.
- Их **нужно доработать**, чтобы они доустанавливали и **фронтенд-тулчейн** (Node.js нужной версии и пакетный менеджер проекта — npm/pnpm/yarn), чтобы весь проект разворачивался одной командой. Пункт «ФРОНТЕНД» в заголовках этих скриптов уже помечает это как TODO.

Только после этой подготовки приступай к работе — по ТЗ с дизайном или по запросам вайбкодера.
