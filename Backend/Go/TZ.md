# ТЗ: Go-сервис SourceCraft (ядро сбора и анализа)

## 1. Назначение

Go-сервис реализует **ядро доступа к SourceCraft**: весь сбор данных через API/CLI, клонирование и анализ репозиториев, нормализацию фактов. C#-бэкенд полностью делегирует эту работу сервису через порты `Backend/CSharp/SourceCraftRepoHealthChecker.Application/SourceCraft/Interfaces`.

Границы:

- Go **не знает** про методику Repo Health Score, веса, категории и рекомендации — только отдаёт факты.
- Go **не хранит** исходный код дольше, чем нужно для анализа.
- Go **не имитирует** security-сканирование: security-данные берутся только из AppSec SourceCraft.

## 2. Соответствие портам C#

| Порт C# | Endpoint (Go) | Тип развёртывания |
|---|---|---|
| `ISourceCraftAuthentication` | `POST /auth/url`, `POST /auth/token`, `GET /auth/me`, `GET /auth/repositories` | Function |
| `ISourceCraftRepositoryCatalog` | `GET /repositories`, `GET /repositories/{id}` | Function |
| `ISourceCraftActivitySource` | `GET /repositories/{id}/activity/commits`, `.../contributors`, `.../releases` | Container (тяжёлое) / Function (лёгкое) |
| `ISourceCraftCollaborationSource` | `GET /repositories/{id}/issues`, `.../merge-requests` | Function |
| `ISourceCraftSecuritySource` | `GET /repositories/{id}/security/findings` | Function |
| `ISourceCraftPipelineSource` | `GET /repositories/{id}/pipelines` | Function |
| `ISourceCraftCodeHealthSource` | `GET /repositories/{id}/code-health` | Container (нужен клон) |
| `ISourceCraftDocumentationSource` | `GET /repositories/{id}/documentation` | Container (нужен файловый состав) |

## 3. Источники данных

- Единственный источник — действующие **API и CLI SourceCraft**. Готовых выгрузок нет.
- AppSec SourceCraft: SAST, SCA, secret scanning — как есть, без собственного сканирования.
- Импорт репозиториев с внешних Git-платформ не требуется.
- Данные закрытых репозиториев обрабатываются только в рамках прав авторизованного пользователя.

## 4. Серверless-развёртывание

Go-часть **частично serverless**, разделение по характеру нагрузки:

| Тип | Что там | Почему |
|---|---|---|
| **Cloud Functions** | auth, каталог, issues/MR, AppSec, CI-статусы | короткие HTTP-вызовы к SourceCraft, укладываются в лимиты FaaS |
| **Serverless Containers** | клон и анализ крупных репозиториев, git-история, TODO/FIXME, bus factor | нет лимита времени FaaS, нужны диск и память под clone/stream |
| **Message Queue** | очередь задач анализа, fan-out по репозиториям | устойчивость, ретраи, разгрузка |
| **Timer trigger** | периодический пересчёт | п. 6 ТЗ (расписание) |
| **Object Storage** | краткоживущий буфер для крупных клонов | только с TTL, без долговременного хранения кода |

Требования serverless:

- **Stateless**: состояние не в памяти инстанса; токены, курсоры, прогресс — во внешних сервисах или в запросе.
- **Idempotency**: повторный вызов endpoint'а не должен ломать данные и не создавать дубли (idempotency key).
- **Cold start**: бюджет на запуск, лёгкие зависимости, минимум инстансов там, где важно.
- **Локальный запуск**: тот же код поднимается как обычный HTTP-сервер (net/http) без облака — для разработки и демо.
- **Таймауты FaaS**: всё, что может превысить лимит, выполняется в Container'е, а не в Function.

## 5. Контракт (REST/JSON)

- Формат — JSON, поля соответствуют C#-моделям из `Application/SourceCraft/Models`.
- Ответ по каждой категории содержит **статус доступности**: `Available` / `NoData` / `Unavailable`. Отсутствие данных — не ошибка и не «плохой» результат.
- Ошибки: `400` (некорректный запрос), `401/403` (нет прав), `404` (репозиторий не найден), `409` (повтор), `502/503` (внешний источник недоступен), `504` (таймаут).
- Частичный сбой одного источника не должен ронять весь снапшот: проблемная категория помечается `Unavailable`, остальные отдаются.
- Все ответы — с `requestId` и временем сбора (`collectedAt`).
- Токен доступа передаётся в заголовке `Authorization`, не логируется.

## 6. Обработка крупных репозиториев

Крупный репозиторий (п. 9.2 ТЗ): **≥ 10 000** отслеживаемых файлов, **или ≥ 20 000** коммитов, **или ≥ 500 МБ** рабочей копии.

- Клон — только во временную директорию/ephemeral FS контейнера, с удалением сразу после анализа.
- Экономия: `--bare`, `--single-branch`, `--depth`, `--filter=blob:none` (partial clone).
- Анализ — потоковый: `git log`, `git ls-files` и т.п. без полного checkout и без загрузки содержимого в память.
- Лимиты по времени, памяти и диску; при превышении — деградация до `Unavailable`/частичных данных, а не падение.
- Исходный код не сохраняется ни в Object Storage (кроме краткоживущего буфера с TTL), ни в логах, ни в ответах.

## 7. Устойчивость

- Ретраи с экспоненциальным backoff для внешних вызовов.
- Rate limiting к API SourceCraft, соблюдение лимитов платформы.
- Circuit breaker на недоступный источник.
- Все операции — с `context.Context` и отменой.
- Идемпотентность повторной обработки одного репозитория.

## 8. Безопасность

- Приватные репозитории — только в рамках прав пользователя, не допускать утечки данных посторонним.
- Токены/секреты не попадают в логи, метрики и трассировку.
- Шифрование данных на стороне хранилищ; минимальный TTL.
- Отсутствие содержимого исходного кода в логах и отчётах.

## 9. Масштабирование и наблюдаемость

- Горизонтальное масштабирование: stateless-функции и контейнеры, конкурентность ограничивается настройками.
- Structured logs, метрики (латентность, ошибки, размеры клонов), распределённая трассировка.
- Метрики по категориям: доля `Available` / `NoData` / `Unavailable`.

## 10. Не входит в зону Go

- Расчёт Repo Health Score, веса, нормализация и агрегация — C#.
- Формирование рекомендаций — C#.
- Веб-интерфейс, рейтинг, выгрузка отчётов — C#.
- Долговременное хранение данных и истории — C# (БД).

## 11. Технологии

- Go (последняя стабильная версия), преимущественно стандартная библиотека; сторонние зависимости — минимально.
- Взаимодействие с SourceCraft через официальный API и CLI; git — локальный.
- Сборка: Docker-образ для Serverless Container + точки входа для Functions.
- Единый бинарник/пакет, из которого собираются и функции, и контейнер.

## 12. Этапы работ

1. **Spike**: реальный доступ к API/CLI SourceCraft и авторизации Я ID, проверка доступных полей.
2. **Auth + Catalog**: эндпоинты авторизации и каталога открытых репозиториев.
3. **Лёгкие источники**: issues, MR, AppSec, CI-статусы (Functions).
4. **Тяжёлый анализ**: клон, git-история, TODO/FIXME, документация, bus factor (Containers).
5. **Очередь и расписание**: периодический пересчёт, ретраи, статусы.
6. **Нагрузочная проверка** на крупном репозитории по границе из п. 6.

## 13. Критерии готовности

- Все эндпоинты из раздела 2 отдают данные, валидные по C#-моделям.
- Отсутствие данных корректно выражается статусом, а не ошибкой.
- Крупный репозиторий обрабатывается без падения и без хранения кода.
- Один недоступный источник не ломает остальные категории.
- Работает локальный запуск без облачной инфраструктуры.
